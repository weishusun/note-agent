## 可用的标签(封闭词表,只能从中选,不能自造)

## 已知领域(其它笔记已经用过的 suggested_domain,按使用次数从高到低)

{known_domains}

## 你要做的判断

1. 先看它能不能**准确**落进上面某一个分类叶子。
   - 能:把 category 设成那个叶子的完整路径(形如 parent/child),
     confidence 给 0 到 1 表示你有多确定。这时 suggested_domain 返回 JSON null。
   - 没有一个叶子真正合适:把 category 返回 **JSON null**(不是字符串 "null"),
     confidence 设为 0,并按第 2 条给出 suggested_domain。**宁可不分类,也不要硬塞。**

2. 当 category 为 null 时,必须给一个 suggested_domain(2 到 8 个汉字的学科/技术领域名)。
   这是全系统唯一允许你自由命名的字段,但请务必克制:

   **优先复用「已知领域」里已有的名字。** 只要这条知识点属于某个已有领域,
   就原样使用那个名字,一个字都不要改。只有当它确实不属于任何已有领域时,才新造。
   这条是整个系统能不能收敛的关键——同一个领域每被叫出一个新名字,聚类就多裂一次。
   不要造近义词(已有「量子力学」就不要再造「量子物理」)。
   领域名要到**学科/技术领域**这一级(如「量子力学」「算法」「AI 工程」),
   不要具体到知识点本身(不要「角动量」「RAG」)。

3. tags:从上面的标签词表里挑 0 到若干个真正贴切的。词表里没有的一律不要写。

4. reason:一句话说明你为什么这么判断。

只描述这条知识点本身,不要参考它顺带提到的其它概念来决定它的归属。

## 输出格式

只输出一个 JSON 对象,不要输出别的内容,形如:
{{"category": "parent/child 或 null", "suggested_domain": "领域名 或 null", "tags": [], "confidence": 0.8, "reason": "一句话理由"}}
其中 category 与 suggested_domain 的 null 是 JSON null,不是字符串。
