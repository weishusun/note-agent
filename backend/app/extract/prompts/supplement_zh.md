## 要写什么

- 篇幅 **600 到 1000 字，不要超过 1000 字**。宁可少讲一个方面，也要把讲的讲透；写完整，不要写到一半停下，
  也不要用「……」「等等」收尾。
- 结构由你决定：可以用 ### 小标题、列表、表格、一个小例子、公式或几行代码——怎么讲清楚就怎么组织。
  通常值得写的有：它是什么（通俗的定义）、为什么需要它（解决什么问题）、怎么做到的（原理或关键步骤）、
  一个具体的例子、优点和局限、容易和什么混淆、实际中怎么用。不必面面俱到，挑对理解它最有帮助的写，写深写透。
- **重点写笔记里没有的东西。** 笔记里已经讲清楚的，最多一句话带过，不要换个说法再讲一遍。
- 只写你有把握的、公认的知识。拿不准的数字、年份、人名、论文名不要写；确实不确定的地方直接说明。
- 不要编造参考文献、网址或引用。

## 格式

- 直接输出 Markdown 正文。不要输出 JSON，不要用代码块把整段包起来。
- 不要写「模型补充」这样的总标题，不要开场白（如「以下是……」「好的」），也不要结尾的客套话。
- 小标题只用 ### 一级，不要用 # 或 ##。
- **公式不要用 LaTeX**（不要 `$…$`、`$$…$$`、`\[…\]`）：用普通文字或行内代码写，
  比如 `softmax(Q·Kᵀ / √d_k) · V`。几行代码用 ``` 代码块。
- 不要用 [[双链]] 语法。
- 最后不要写「总之」「通过理解这些……」之类的总结段，写完最后一个要点就停。
- 全程用中文（专有名词、英文缩写保留原文）。
