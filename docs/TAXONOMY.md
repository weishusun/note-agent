# TAXONOMY — 分类体系设计

> 本文件说明**为什么**这么分类。实际的分类数据在 `vault/taxonomy.yaml`。
> 两者冲突时以 yaml 为准,但改 yaml 前必须符合本文件的规则。

---

## 1. 为什么是「浅树 + 受控标签」

| 方案 | 失败模式 |
|---|---|
| 纯树(单一父类) | 一条笔记常常同时属于两个分支,树逼你二选一,信息丢失 |
| 纯标签(自由多标签) | 三个月后 300 个标签,其中 200 个只用过一次,导航等于没有 |
| **浅树 + 受控标签** | 树回答「它住在哪」,标签回答「它还跟什么有关」 |

具体规则:

- 分类树**最多两层**,`category` 值形如 `ai-engineering/rag`
- 每条笔记**只能挂在一个叶子**上
- 标签是**封闭词表**,笔记的 tags 必须是词表的子集,最多 6 个

---

## 2. 分类还是标签?

一个词该做子分类还是做标签,用这个判据:

> **如果它只会出现在某一个一级分类下 → 做子分类。
> 如果它会横跨两个或以上的一级分类 → 做标签。**

例:

- 「向量检索」几乎只出现在 AI 工程下 → 但它同时是 `rag` 子分类的核心内容,所以做**标签**依附在 rag 下即可
- 「幂等」会出现在数据工程、软件工程、AI 工程 → **标签**
- 「动态规划」只出现在计算机基础下 → 但它够大且够独立 → 可以考虑做 `cs-fundamentals/algorithm` 下的**标签**,不必单开分类

拿不准的时候默认做标签。标签删起来没有代价,分类删起来要重挂一批笔记。

---

## 3. 新增分类的门槛

这是整个体系不崩的关键。**创建分类的门槛必须比创建笔记高一个数量级。**

新增一个**子分类**,必须同时满足:

1. `inbox/` 里已经积压了 **≥ 5 条**同一主题、现有分类都装不下的笔记
2. 新分类一开就能装下 **≥ 3 条**已存在的笔记(不是为未来预留)
3. 它不是某个现有子分类的近义词

新增一个**一级分类**:

- 半年内不应该发生。真需要,说明你的知识领域发生了结构性变化,那时坐下来重新设计整棵树,而不是往上贴。

**任何分类的新增都必须由整理循环提议 → 你人工确认。录入循环永远不能创建分类。**

反过来,**删除/合并**分类是整理循环的日常工作:
- 某分类下 > 20 条 → 提议拆分
- 某分类下 < 2 条且超过 60 天没新增 → 提议并入相邻分类

## 4. 种子分类树

下面这棵树是**起点,不是终点**。它按当前技术方向铺了 4 个一级分类、14 个叶子。

```
ai-engineering        AI 工程
├── agent             Agent 与编排
├── rag               检索与上下文
├── prompting         提示工程
├── model             模型与推理
└── evaluation        评估与可靠性

cs-fundamentals       计算机基础
├── algorithm         算法
├── data-structure    数据结构
└── system            系统与网络

data-engineering      数据工程
├── modeling          数据建模
├── pipeline          管道与编排
└── storage           存储与查询

software-engineering  软件工程
├── backend           后端
├── frontend          前端
└── tooling           工具与工程化
```

**你要做的事**:照着自己最近三个月实际在记的东西过一遍。
- 有哪个叶子你想不出能往里塞什么 → 删掉它
- 有什么东西你确定会经常记但无处可放 → 加一个叶子
- 如果你也想把非技术内容丢进这个库(语言学习、生活方法论之类),加一个平级的一级分类,别硬塞进现有的四个里

**宁可少,不要多。** 前两周分不准很正常,那些笔记会落进 `inbox/`,等第 4 周整理循环上线时一起处理。这比一上来就铺 40 个空分类健康得多。

---

## 5. 标签词表的维护

初始 18 个,原则同上:

- 只收**会横跨多个分类**的词
- 加标签前先看能不能用现有的
- `待深入` 和 `面试常考` 这类是**工作流标签**,不描述内容,描述你打算怎么用它 —— 这类很有用,但控制在 3 个以内

标签的膨胀比分类慢,但一样致命。整理循环每次跑要报告:哪些标签只有 1 条笔记在用(候选删除),哪些两个标签的共现率 > 80%(候选合并)。
