# TAXONOMY — 分类体系设计

> 本文件说明**为什么**这么分类。实际的分类数据在 `vault/taxonomy.yaml`。
> 两者冲突时以 yaml 为准,但改 yaml 前必须符合本文件的规则。

**版本:v2** — 第 3、4 节重写:分类不再预先设计,改为从笔记聚类中生长。

---

## 1. 为什么是「浅树 + 受控标签」

| 方案 | 失败模式 |
|---|---|
| 纯树(单一父类) | 一条笔记常常同时属于两个分支,树逼你二选一,信息丢失 |
| 纯标签(自由多标签) | 三个月后 300 个标签,其中 200 个只用过一次,导航等于没有 |
| **浅树 + 受控标签** | 树回答「它住在哪」,标签回答「它还跟什么有关」 |

规则:

- 分类树**最多两层**,`category` 值形如 `physics/quantum-mechanics`
- 每条笔记**只能挂在一个叶子**上
- 标签是**封闭词表**,笔记的 tags 必须是词表子集,最多 6 个

---

## 2. 分类还是标签?

> **只出现在某一个一级分类下 → 做子分类。
> 横跨两个或以上一级分类 → 做标签。**

拿不准时默认做标签。标签删起来没有代价,分类删起来要重挂一批笔记。

### 两层够不够?

够。**分类是粗过滤,定位靠搜索和别名。**

`physics/quantum-mechanics` 这个叶子将来会装几十条笔记,这不是问题。做知识库最常见的失败是把分类树做到四五层,以为要靠一路点击找到笔记——实际上没人这么用,超过三层你自己都记不住东西放在哪,最后还是回去搜。

所以「角动量」是 **tag**,不是分类。「量子力学」是分类,「physics」是它的父级,到此为止。

---

## 3. 分类从哪里来:聚类,不是设计

**你不需要、也不可能预先列出自己将来会记的所有领域。** 任何人坐下来凭空列出的分类树,和他半年后实际记的东西的分布,都对不上。

核心规则:

> **分类由「一批笔记的聚类」产生,不由「单条笔记」产生。**

这两者的差别就是全部。危险的从来不是自动创建分类,而是**写一条笔记时顺手创建一个分类**——那必然导致大量只有一篇笔记的空壳。而如果创建依据是「inbox 里已经堆了 9 条量子力学的东西」,这个分类天然就有内容支撑,不可能是空的。

### 流程

1. **录入循环**遇到现有分类装不下的笔记 → 落 `inbox/`,`category: null`,填一个 `suggested_domain`(自由文本,比如「量子力学」)
2. `suggested_domain` **不进 taxonomy**,它只是聚类线索。这是全系统唯一允许模型自由生成的字段
3. **整理循环**扫 inbox,按 `suggested_domain` 聚类,达到阈值就写提议进 `.noteagent/proposals.yaml`
4. **你确认**之后才写入 `taxonomy.yaml`,并把相关 inbox 笔记重新归档

### 门槛

| 类型 | 门槛 |
|---|---|
| 新增二级分类 | 同聚类 ≥ 4 条 |
| 新增一级分类 | 同聚类 ≥ 8 条,且与所有现有一级分类的语义距离超过阈值 |
| 合并 | 两分类语义中心相似度超阈值,或其一 < 2 条且 60 天无新增 |
| 拆分 | 单叶子 > 20 条 |

一级分类的额外语义距离判断是为了防止「AI 工程」旁边冒出一个「人工智能」。

### 提议必须带证据

```
提议新建一级分类 physics（物理）
  依据：inbox 中 9 条笔记的 suggested_domain 聚为此类
  证据：角动量算符的对易关系.md / 泡利矩阵.md / 简谐振子.md ...（可点开）
  建议二级：quantum-mechanics(6) / classical-mechanics(3)
  [ 批准 ]  [ 改名 ]  [ 拒绝 ]  [ 再等等 ]
```

**没有证据列表的提议不允许生成。** 你要能点开看那 9 条到底是什么,才能判断这个分类该不该建、该叫什么名字。

---

## 4. 冷启动:从空 taxonomy 开始

`taxonomy.yaml` 可以完全为空,这是**推荐的起步方式**,不是异常状态。

- **第一周**:你记的所有东西全进 `inbox/`。agent 只做解析和打 `suggested_domain`,不做分类。这看起来像系统没工作,其实是在积累聚类证据。
- **第一次整理循环**:给你五六个提议,每个都带证据。你点几下,taxonomy 就有了。
- **之后**:新领域出现时自动重复这个过程,你不需要做任何前置设计。

这样长出来的分类树,比凭空想出来的准得多——它反映的是你**实际记了什么**,而不是你**以为自己会记什么**。这两者的差距通常很大。

**唯一需要你判断的地方**是确认提议时的命名和边界。那恰恰是模型做不好而你能一眼看出的事。

---

## 5. 标签词表的维护

同样从空开始,同样靠聚类生长。原则:

- 只收**会横跨多个分类**的词
- 加标签前先看能不能用现有的
- `待深入`、`面试常考` 这类是**工作流标签**,不描述内容而描述你打算怎么用它 —— 很有用,但控制在 3 个以内

整理循环每次跑要报告:哪些标签只有 1 条笔记在用(候选删除),哪些两个标签共现率 > 80%(候选合并)。
